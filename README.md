### 🤖 Failsim-AI
Helps robotics teams discover why simulated robots fail by running physics-based tests across robot and object conditions, then summarizing likely causes and possible fixes. It aims to cut manual robot testing and make failure patterns easier to investigate. The README describes deployment on a Vultr VM.

`Python` `PyBullet` `NumPy` `FastAPI` `React` `Vite` `Tailwind CSS` `Google Gemini`

[📂 Repository](https://github.com/Eng-Hu-snain-Ali/Failsim-AI) · [📖 README](https://github.com/Eng-Hu-snain-Ali/Failsim-AI/blob/main/FailSim-AI-main/README.md)

### 🎙️ VoiceOps
Saves people from manually reviewing calls and writing up next steps. It converts recorded or uploaded audio into structured output: transcript, summary, sentiment, action items, risks, decisions, and a draft follow-up email. The backend uses Node.js built-in modules, the web app is vanilla HTML/CSS/JavaScript, and a React component is included for a native.builder integration.

`Node.js` `JavaScript` `React` `Speechmatics` `LLM API`

[📂 Repository](https://github.com/Eng-Hu-snain-Ali/Voiceops-Main) · [📖 README](https://github.com/Eng-Hu-snain-Ali/Voiceops-Main/blob/main/README.md)

### 🦠 OutbreakAI
A decision-support prototype: it records disease activity by region, assigns a risk level, tracks case trends, and suggests responses such as preparing hospital overflow capacity or running vaccination drives. Weather data comes from OpenWeatherMap.

> **Status:** the live risk score is currently rule-based. The included machine-learning model artifacts are not used in the API's risk decisions, and this is not a validated outbreak-prediction system.

`Python` `Flask` `Flask-SQLAlchemy` `SQLite / PostgreSQL` `scikit-learn tooling`

[📂 Repository](https://github.com/Eng-Hu-snain-Ali/OutbreakAI) · [⚠️ Known limitations](https://github.com/Eng-Hu-snain-Ali/OutbreakAI/blob/main/README.md#known-limitations)

### 🚌 Bus-Seat-Reservation-System
A front-end prototype for searching bus trips, comparing sample schedules, choosing seats, and displaying a booking confirmation.

> **Status:** schedules and seat availability are hard-coded, and search and booking are simulated in the browser. Seats are marked as booked only for the current page session. No real reservations or persistence, and no backend or database.

`HTML` `CSS` `Vanilla JavaScript`

[📂 Repository](https://github.com/Eng-Hu-snain-Ali/Bus-Seat-Reservation-System) · [💻 Booking code](https://github.com/Eng-Hu-snain-Ali/Bus-Seat-Reservation-System/blob/main/Bus%20go/script.js)
